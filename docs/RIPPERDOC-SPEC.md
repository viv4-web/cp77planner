# Ripperdoc screen specification

Generated by `tools/ripperdoc_spec.py` from the game's ripperdoc UI export (WolvenKit JSON, read only, kept in `~/work/cyber-art/raw/ui/`, never in this repo). It holds layout numbers, token values, widget and sequence names, and our own descriptions. No game text is copied: captions and descriptions are not quoted, our UI gets its own strings. Companion file: `docs/RIPPERDOC-ANIMATIONS.md` (all 69 sequences). Reference render: `tools/ripperdoc_render.py`.

> **Source version.** The files are from the game 2.5 install. The export headers report WolvenKit 9.1.0 and `GameVersion 2310`, which is only WolvenKit's header value.

## 1. Reading the numbers
- The library resolution is `UltraHD_3840_2160`: **every px value is on a 3840x2160 design grid.** At 1920x1080 multiply by 0.5. For CSS use one unit `--u: calc(100vw / 3840)` (or a container-relative equivalent) and write sizes as `calc(N * var(--u))`; this keeps fonts and gaps proportional.
- **Anchor** = the point of the parent the widget hangs from (TopLeft, Centered, BottomRight, ...; the `...Fill...` anchors stretch along one axis, `Fill` along both). **Margin** = L T R B offsets from that point: the widget is shifted by (L - R, T - B); for Fill axes the margins shrink the box. **Padding** insets the children. `fitToContent` images take the natural size of their atlas part.
- Opacity multiplies down the tree. Each widget has its own render transform (scale, translation, rotation about a pivot, default centre), which animations drive. Anything with `visible = false` or opacity 0 at rest is an animation start state, not absent.

## 6. Animations
69 sequences, 290 target definitions, interpolators: Transparency 245, Translation 140, Scale 109, Video 49, Effect 21, Size 14, Rotation 3, Margin 1. All are `FromTo`. The full table (target widget, from -> to, duration, delay, easing, CSS) is in `docs/RIPPERDOC-ANIMATIONS.md`. Mapping rules:

| ink | CSS | Note |
|---|---|---|
| Transparency | `opacity` | exact; our rule: transform/opacity only |
| Translation / Scale | `transform: translate() scale()` | exact; translate values are design px (`u`), scale about the widget pivot (default centre) -> `transform-origin` |
| Rotation | `transform: rotate()` | only `BG_animation`: 3 endless rotations (360/720/1080 over 18 s); unit assumed degrees |
| Size | scaleX/scaleY from the anchored edge | approximate: the game animates the box size (wipe-in of panels); CSS-only rule avoids animating width/height |
| Margin | translate by the margin delta | one use (`HideTooltip`) and it does not change (from = to) |
| Effect (LinearWipe) | `clip-path: inset()` or a gradient `mask` | approximate: 21 interpolators drive a wipe `transition` 0 -> 1; the wipe angle/direction is not in the data |
| Video | `<video>` play from t0 to t1 | name of the clip is given in the table; see section 8 for timings |
| Events | Marker = script callback; StopVideo = pause; SetVisibility; PlaySound | 22 markers (all at t = 1 s in the zone intros: the 'intro done' signal), 22 StopVideo, 2 SetVisibility, 1 PlaySound |

Easing: `Linear` -> `linear`; the others map as in the table below (standard ease curves); `EasyOutIn` (4 uses) has no CSS equivalent and is approximated by `linear`. ink `Qubic` is a cubic curve; `Quintic` a quintic one.

| ink type / mode | CSS timing function |
|---|---|
| Quadratic / EasyIn | cubic-bezier(.11,0,.5,0) |
| Quadratic / EasyOut | cubic-bezier(.5,1,.89,1) |
| Quadratic / EasyInOut | cubic-bezier(.45,0,.55,1) |
| Qubic / EasyIn | cubic-bezier(.32,0,.67,0) |
| Qubic / EasyOut | cubic-bezier(.33,1,.68,1) |
| Qubic / EasyInOut | cubic-bezier(.65,0,.35,1) |
| Quartic / EasyIn | cubic-bezier(.5,0,.75,0) |
| Quartic / EasyOut | cubic-bezier(.25,1,.5,1) |
| Quartic / EasyInOut | cubic-bezier(.76,0,.24,1) |
| Quintic / EasyIn | cubic-bezier(.64,0,.78,0) |
| Quintic / EasyOut | cubic-bezier(.22,1,.36,1) |

## 8. Paperdoll flow
What the data proves, then what is inferred (the controller scripts are not part of the export).

**From the data**
1. Idle: `Paperdoll_default_tab` shows the body loop (`female_body_loop` / `male_body_loop`, looping, autoplay controller) and one hover sprite per zone (atlas parts `wo_*` / `ma_*` of `woman_body` / `man_body`, sized to the zone and offset to sit on it).
2. Hover: `hover_area` fades a sprite from opacity 0 to 1 in 0.233 s (linear), `hoverover_area` fades it back out over the same time. The two sequences are keyed on a single sprite in the file (the woman arms sprite), so the game must retarget them per zone at runtime.
3. Select: the zone's intro sequence runs. Default tab: translate and scale up (x2.9 for the man operating system up to x9 for the woman integumentary, 0.9 s, exponential in-out) while fading out (0.17-0.33 s, delayed 0.2-0.4 s); the zone canvas translates and scales in from 0.21-0.7 to 2 (1.8 for the man's body-wide zones; 0.9 s, exponential in-out) and fades in (0.1 s, delayed 0.3-0.4 s); the zone clip plays from 0 (5.033 s window, real time; our clips are 3.6-4.0 s, so they end on their last frame and hold). A Marker event at 1 s signals that the intro finished.
4. Leave: the outro reverses the zoom (0.533 s, quartic in-out): default tab and canvas return to their rest transform, the canvas fades out (0.167 s) and a StopVideo event at 0.533 s stops the clip.
5. Man vs woman: identical structure; the man sequences are prefixed `M_` and use slightly different zoom/translate numbers (and different clips, `man_*`).
6. Entering the screen: `Paperdoll_default_tab_intro` slides the default tab in from 550 design px below while it scales 2 -> 1 (0.9 s, exponential out) and fades in (0.3 s, delayed 0.133 s, sine out).

**Inferred (needs a game check)**
- Which zone is hovered or selected is decided by the controller from the slot list the player hovers; each zone has a slot panel anchor (section 3) and presumably the sprite, intro and outro with the same name stem.
- While a zone is open the slot panel for that zone is shown and the other sprites stay hidden; the hover sprites are at opacity 1 in the file but must start hidden (only the woman arms sprite is stored at 0.5).
- The capacity and armor meters are at opacity 0 at rest and are faded in by intro sequences (`purchase_popup_intro` touches both; `capacity_meter_bars_intro` and `meter_intro_*` animate the bars).

**Planner mapping (proposal, no code yet).** Idle = `<video loop>` of the body loop + CSS-hidden hover sprites; hover = opacity transition 0.233 s linear; select = one CSS class that runs the zone zoom as `transform` transitions (0.9 s `cubic-bezier(.87,0,.13,1)`) and starts the zone `<video>` from 0; leave = reverse over 0.533 s (`cubic-bezier(.76,0,.24,1)`) and `pause()`. Motion 'Off' / reduced motion: show the `.webp` poster of the clip and cut instead of zoom. Phone: use the `_sm.webm` clips.

## 9. Decisions and open points
**Decided (Vivek)**
1. **Version.** The files are from the 2.5 install; `GameVersion 2310` is only WolvenKit's header value.
2. **Behaviour is ours.** Controller scripts are not in the data. The data gives layout, art, timings and colors; the hover / select / open / close flow (section 8) is our own design.
3. **Background.** `background.inkatlas` is used as the screen background.
4. **Wipe effect.** Rendered as a CSS mask-gradient wipe with the same duration and easing.
5. **Emissive colors (> 1.0).** The base color is clamped to sRGB and the excess becomes a glow (`text-shadow` / `drop-shadow`); `tools/ripperdoc_layout.py` writes it as `--t-*-glow`.
6. **Fonts.** Rajdhani from its open-source release (SIL OFL), self-hosted in `src/fonts/`; the game TTFs are not used. The game's digital readout font (only used for two decorative `888`/`999` ghost counters) is replaced by Share Tech Mono (OFL), used for small numeric captions.

**Still open**
1. **Video interpolator oddities.** `Video from -> to` looks like a playback window in seconds (0 -> 5.033 in 5.033 s = play once). A few entries look like leftovers (woman `frontalCortex_intro` plays 0 -> 0.068 s; several Video definitions target `Root`). We play every zone clip once from 0 and hold the last frame.
2. **Targets that are not in Root (16 definitions)** in `ripper_id`, `warnning`, popups and a few others use child paths that exist only in other library items or are resolved by script; they are listed with their raw path. Many sequences (e.g. `default_tab_intro`, 25 definitions, all path `[]`) probably play on other library items, so their target names are only reliable for the paperdoll, meter and `warnning` sequences.
3. **Wipe angle and softness** are not in the data (only progress 0 -> 1); our mask wipe is left-to-right.
4. **Layout engine details.** The simplified rules in section 1 reproduce the idle screen (`incoming/screens/ripperdoc-reference.png`), but panel sizing for `fitToContent` panels and uniform grids is approximate; inventory cell sizes (224x202 / 216x194) are known, cell counts and wrapping are ours.
5. **Slot ordering and counts** per zone panel are not in the widget tree (panels are empty); they come from our game data (`docs/GAME-DATA.md`).

### 10.5 What the export does not contain, and what we did instead
- Atlases missing from the export: `atlas_inventory/corners_equipped`, `atlas_inventory/texture_1slot`, `atlas_inventory/texture_1slot_iconic`, `hub_atlas/ico_cafting_crafting`. The tile's hatch texture (`texture_1slot`) is a CSS gradient at the game's opacity (0.03); the equipped corner marks (`corners_equipped`) and the iconic texture are left out; the cyberware empty socket (`fullscreen_elements/socket`) is replaced by the `icon_add` plus part.
- `tooltip_style.inkstyle` is not in the export: tooltip colors are the widgets' own default tints (background `#0E0E17`, stroke `MainColors.MildRed`, separator `#451715`). Nine-slice margins are not in the atlas files: the tile parts are stretched (as in the game's `Fill` setting); the tooltip uses a 9-slice mask (`-webkit-mask-box-image`, corner 29 px) where the browser supports it, and stretches otherwise.
- `Operating System` decks have no `iconPart`; their `iconName` (`militech_paraline`) is not a part of any exported atlas, so the 15 records show the generic cyberdeck icon (`item_icons/icon_cyberdeck`). Reported by `tools/cyberware_icons.py`.
